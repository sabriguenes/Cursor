### Deviations in the fresh chat

Findings, not pass conditions.

1. The Foreman wrote its own dispatch prompt for the prerequisites sub-agent (a role sentence plus restated output limits) instead of tool path, tag and grep instruction. Cursor blocked that sub-agent request under the provider's usage policy before any tool call; the same block dispatched with only path, tag and grep instruction passed twice. The Foreman then ran the checks in its own context, which the tool does not define, and its shell output carried login-status account fields and a masked key into the chat context. Addressed by: "Sub-agent dispatch" now holds one fixed template, copied unchanged with no other text, and defines a failed sub-agent: record its error line, stop with `stopped: sub-agent <tag>: <error line>`, retry only on the human's word, never run the block in the orchestrator's own context; the login lines of `prerequisites-instructions` print only login state and kind.
2. Model switch: after that block, the orchestrating chat ran on a fallback model for the rest of the run. The switch point is inferred from the log time of the block, since the logs name no fallback model. The CLI calls are unaffected: the Claude streams and the Codex session file name their models. Addressed by: no tool rule can pin the orchestrating chat's model; the mitigation removes the trigger, namely the fixed dispatch template in "Sub-agent dispatch" (no restated limits) and the filtered login commands in `prerequisites-instructions` (no identity fields in context).
3. Nested quoting: a command wrapped in `powershell.exe -Command "..."` lost a variable to the outer shell's expansion; run directly, it worked. Addressed by: "Calling the CLIs" step 8, every command other than the `-File` call to `run.ps1` runs directly in the agent shell, and a command for another `powershell.exe` is passed in single quotes.
4. Artifact reuse: the new step 2 call reused the artifact name `step-2` and overwrote the interrupted call's stream, against the unique-artifact checklist line. Addressed by: "Resume" step 4, a call with a prompt or stream but no line under Calls is recorded as `interrupted`, its files are kept, and the new call gets a new artifact name such as `<artifact>-r<k>`.
5. Codex model: `codex exec --json` streams carry no model, so `RUN.md` recorded `model not in stream` for every Codex call. The `thread.started` thread id names the session file `CODEX_HOME/sessions/**/rollout-*-<thread id>.jsonl`, whose first `"model":"..."` match is the model. Addressed by: `run.ps1` reads the thread id from the Codex stream, finds that session file and writes the model to `logs/model-<artifact>.txt`; "Calling the CLIs" step 7 records Codex's model from that file, or `model unknown` when it is missing.

## Limits

- The setup sub-agent ran the prerequisites block inline instead of dispatching a sub-agent, because a sub-agent cannot start another.
- Test-harness overlap: a parallel fixture sub-agent wrote the pointer skill into the same scratch home during the first setup run. The setup agent reported it as not its own write. The setup test was rerun on a fresh copy of `foreman.md` with a scratch home of its own and no parallel agent; the hash and report rows record that rerun.
- In the rerun, the Claude CLI wrote `.claude.json`, `.claude/backups/` and an empty application-data folder into the scratch home while the prerequisite commands ran. These are not setup writes and not the two target files.
- The pass condition for a config without `[windows]` was amended to the procedure's three lines (separating blank line, header, `sandbox` line) before that row was recorded.
