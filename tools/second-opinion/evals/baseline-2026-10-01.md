# Baseline 2026-10-01

First series, Windows with PowerShell. Orchestrator: a chat model in Cursor. Opus 5.5 in the Claude Code CLI on a subscription. Codex `gpt-6-astra`, read-only. Generalized for publication: ids, paths, branch names and hashes of the original repo are omitted; the paper ids are the synthetic ones of the template.

## Golden

| Check | Result | Evidence |
|---|---|---|
| Push block | pass | all 30 Claude runners of the series name both patterns. Task 1: `git push` denied, did not run. Task 5 runner also blocks `git commit`. |
| Scope request | pass, with a rule change | task 4: `__init__.py` untouched, `SCOPE REQUEST` reported, human approved, file into the plan, step rerun. The old rule would have demanded a new Cursor plan; it did not fire and was changed. |

## Deviations to keep in mind

- Task 5 seeds differ from the original task prompt's specification. Reruns use `seeds/`.
- Task 5 referee test had 10 cases in one file: 9 failed, 1 passed. Only one test covered the single finding. Since then: exactly one test function per finding, run as `<file>::<test>`.
- The sweep runner did not block `git commit`; the plugin-review runner of task 1 had no push block. Both are golden rules since.

## Limits

- Sweep evidence comes from three small files. Partial reads and large modules are not covered.
- Watchdog stall and cap were proven in probes and by self-test, not by a stalled series run.
